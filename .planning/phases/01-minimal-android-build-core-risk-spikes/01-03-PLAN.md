- pub trait Render: Send + 'static { fn configure(&mut self, sample_rate: u32, channels: u16); fn render(&mut self, out: &mut [f32]); }
- pub struct OutputOptions has impl Default (device: Device::Default, channels: 2, follow_default: true, release_after: Some(5 min), ...)
- impl<R: Render> Output<R>: pub fn open(options: OutputOptions, renderer: R) -> Result<Self, OpenError>; pub fn device_name(&self) -> &str; pub fn sample_rate(&self) -> u32; pub fn channels(&self) -> u16; pub fn clock(&self) -> Clock; pub fn take_errors(&mut self) -> Vec<OutputError>
- Clock: pub fn played(&self) -> Duration
- pub fn output_device_names() -> Result<Vec<String>, OpenError>   // lists only, opens nothing

cpal 0.18.2 AAudio host (src/host/aaudio/mod.rs):
- Device(None).description() returns the name "Default Device" (line 572). Opening Device::Default therefore LEGITIMATELY reports device_name() == "Default Device" even when playback works. This corrects RESEARCH.md's Code Example, which says to check device_name() is not "Default Device". The JNI enumeration proof must come from output_device_names(), not from the opened Output.
- If the JNI AudioManager.getDevices call fails, devices() falls back to only [Device(None)], so output_device_names() returns only ["Default Device"]. That is a FAIL signal (RESEARCH.md Pitfall 6).

The planner compile-verified a spike of exactly this shape for aarch64-linux-android with zero warnings: a Tone renderer, output_device_names(), Output::open(OutputOptions::default(), Tone{..}), sleep 3 s, clock().played().

Launch component: rocks.spotifast.spotifast/android.app.NativeActivity. Package: rocks.spotifast.spotifast.

Raw screencap (no -p): `adb exec-out screencap` writes a header then RGBA8888 pixels. Header length = total_bytes - width*height*4. The first two little-endian u32 are width and height. Python stdlib (struct) is enough; PIL is not needed.
