<objective>
Make spotifast's `[lib]` crate compile, link and package for Android, add the `android_main` entry point that renders a minimal egui surface, and keep desktop gates green.

The planner ran a throwaway probe: a copy of the repo, outside the repo, with `cargo check` and then `cargo build` for aarch64-linux-android. It found exactly three Android compile blockers. The `.so` linked successfully once all three were fixed.
1. `rfd` 0.17.2 fails inside its own crate. `rfd-0.17.2/src/backend.rs` has only macos, windows, wasm32 and linux/bsd arms, so the dependency itself must not be built for Android. Gating call sites alone is not enough, which corrects RESEARCH.md Pattern 2. There are also FOUR code sites, not the two RESEARCH.md lists.
2. The pinned eframe rejects `accesskit` together with `android-native-activity`: crates/eframe/src/lib.rs lines 147-152 contain `compile_error!("accesskit feature is only available with android-game-activity")`. Cargo features are additive, so the existing top-level `eframe` line, which has accesskit, must move to a non-Android target table.
3. `src/credentials.rs` lines 183-189 define `let store` only for linux, macos and windows, which gives E0425 on Android.

Purpose: AND-01. These changes are the narrow, compile-only exceptions Phase 1 needs. The full desktop-feature stripping is AND-10 in Phase 2 and stays out of scope here.
Output: a debug APK at target/debug/apk/, plus a green desktop gate.
</objective>
