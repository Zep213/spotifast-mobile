<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub (rust-mobile/cargo-apk) → local toolchain | Build tool compiled from a git HEAD runs with the developer's privileges |
| Docker Hub (rust:1.98.0-bookworm) + Debian apt → gate container | Third-party image and packages execute the build |
| crmne/egui fork → app | The pinned fork must contain the GL-resume fix being relied on |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SC | Tampering | cargo-apk git install | mitigate | Install only from github.com/rust-mobile/cargo-apk (same org as android-activity), with `--locked`, and record the exact commit SHA in the SUMMARY for audit |
| T-01-02 | Tampering | Docker gate image | mitigate | Use only the official library image `rust:1.98.0-bookworm` and Debian's signed apt repositories; the container runs as the host uid with only the repo and cargo cache mounted, no `--privileged` and no host network changes |
| T-01-03 | Tampering | [patch.crates-io] fork pins | mitigate | D-06 ancestry proof against an upstream merge SHA. Pins stay rev-locked by full SHA and are not changed (AGENTS.md, check-dependency-sources.py) |
| T-01-04 | Elevation of Privilege | Docker usage | accept | User is already in the `docker` group; the script adds no new privilege, and the container does not run as root at gate time |
</threat_model>
